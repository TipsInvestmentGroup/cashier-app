Building a Collection Template

A field guide for TIPS admins: what to select and fill in, in order, to turn a collection form you can picture into one cashiers can actually use.

A template is the blueprint for one kind of collection: what gets asked, in what order, and how it's entered. Every template is built from three nested pieces —

  • Stages — the big steps of the form (e.g. "Sales", "Bills"). Each stage picks one entry mode.
  • Sections — groups of related fields inside a stage (e.g. "Payment Channels").
  • Fields — the actual inputs (e.g. "Cash", a number).

Build from the outside in: name the template, add a stage, then fill that stage with sections and fields. The rest of this guide walks through each choice in the order the editor asks for it.

1

Name the template

Give it a name a cashier or manager would recognize on sight — Restaurant & Bar Collection, not Template 3. The description is optional but worth a sentence: it's the only hint anyone gets before opening the form.

Leave "Active" checked. An inactive template disappears from the Collection Sessions picker — use it to retire a template without deleting its history.

2

Add a stage

Click + Add Stage and name it after what happens in it — Sales, Bills, Cash Reconciliation. Two settings sit next to the name:

  • Optional stage — check this if a cashier can finish the session without ever opening it (e.g. a "Damages" stage that's usually empty).
  • Entry mode — covered next; it decides how the stage gets filled in.

Stages run top to bottom in the order you leave them, so put the one that has to happen first — usually Sales — at the top. Use the ↑ ↓ arrows to reorder.

3

Pick an entry mode

This is the choice with the biggest effect on the cashier's day. Match it to how the work actually happens at the outlet:

Entry modeHow it worksUse it when…
Single StaffOne form, one staff member, save, then the next.Each cashier hands in their own numbers separately, like the original Daily Collections form.
Multi‑Staff GridOne table, every active staff member as a row, one save for everyone.You collect the same few numbers from the whole floor at once — e.g. end‑of‑shift tips.
Batch EntryPick a subset of staff first, then fill just those rows.Only some staff are relevant this round — e.g. only the waiters who worked a private event.
Excel ImportUpload a spreadsheet; rows are matched to staff by name and to fields by column header.The numbers already exist somewhere else — a POS export, a supervisor's tally sheet.
POS Auto SyncReserved for a future direct POS connection — currently shows "not connected yet".Don't pick this yet. Use Single Staff or Grid and switch later once a POS integration exists.

Excel Import needs a matching header row. The spreadsheet must have a column named Staff/Attendant/Name, plus one column per field whose header contains that field's label — so name fields to match what the sheet will say.

4

Add sections

Inside a stage, click + Add section for each logical group of fields. Typing a name shows suggestions — SALES, PAYMENT_CHANNELS, BILLS, DISCOUNTS, CANCELLATIONS, EXCESS, CASH_RECON — but any label works.

Check Mandatory on a section that must never be skipped in practice, even though nothing currently blocks skipping it — it's a note to future-you and to whoever edits the template next, not an enforced rule by itself. (Individual fields marked Required, in the next step, are what actually get enforced.)

5

Add fields

Click + Add field inside a section for every value you need to capture. Give each one a plain label and pick its type:

Field typeRenders asUse it for
NumberNumeric inputCash, System Sales, discounts — anything counted or measured.
TextFree textA reference number, a short note.
SelectFree text (typed value)A short category the cashier types rather than picks — reasons, labels.
Staff PickerDropdown of active staffWhoever the entry is about — this doubles as the "which staff is this row for" answer in Single Staff mode.
Person PickerDropdown of persons/customersA named customer, director, or other person tied to the entry.
DateDate pickerA date other than the session's own date.
BooleanCheckboxA yes/no flag — "Approved by manager?", "Till balanced?".

Check Required on any field the form should refuse to save without — this one is enforced, at save time.

Grid and Batch modes skip picker columns. In a table where every row already is one staff member, a Staff Picker or Person Picker column has nothing left to ask — the row itself is the answer. Keep those two field types for Single Staff stages.

6

Set validation rules (optional)

Rules sit below the stages and apply to the whole template. Each rule type is fixed — you configure it with a small JSON object, not free-form logic:

RuleWhat it doesConfig
Stage SequenceBlocks a stage until every earlier required stage has at least one completed entry.— none needed
Cash ≤ System SalesBlocks saving if cash collected exceeds system sales, unless an excess-reason field is filled.
{"cashFieldKey":"CASH",
 "systemSalesFieldKey":"SYSTEM_SALES",
 "reasonFieldKey":"EXCESS_REASON"}
Discount Approval LimitAbove the limit, the entry still saves but goes to Collection Approvals for a manager's sign-off instead of completing outright.
{"fieldKey":"DISCOUNT","limit":50000,
 "approverRole":"MANAGER"}
No Negative BalanceRejects a negative value in the named field.
{"fieldKey":"CASH"}
— omit fieldKey to check every number field
Required FieldNo‑op — required fields are already enforced per‑field in step 5.— none needed

The FieldKey values in a rule's config must match a field's key exactly — that's the all‑caps code shown once you've named the field (e.g. naming a field "Discount" gives it the key DISCOUNT).

7

Save, then test it as a cashier would

Click Save Template. Then open Daily → Collection Sessions, pick the outlet and this template, and open today's session — filling it out yourself once catches a mislabeled field or a rule that's stricter than intended before a cashier ever sees it.

Editing later: a stage, section, or field that already has real entries against it can't be deleted — the save will fail with a clear reason instead of silently losing data. Renaming labels is always safe; only removal is blocked once data exists.

After you save

The template appears at Daily → Collection Sessions for every cashier, manager, and admin — that's where the form actually gets filled in, day to day. Anything pending a discount sign‑off shows up for managers at Collection Approvals. The Standard Staff Collection template is untouched by any of this — outlets that don't need the new form keep using the original Daily Collections screen exactly as before.
